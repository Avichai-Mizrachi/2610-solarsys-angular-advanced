# Space Rescue Mission Planner

## Your mission

The space station needs help choosing rescue missions for its drone, **Comet**.
Build a small TypeScript program that filters missions, calculates rewards, and
prints a mission preview. No browser, Angular, server, database, or interactive
terminal input is needed.

This exercise is for absolute beginners. Each step tells you which file to
create, what code to write, and how to check the result.

| Step | Activity |
| --- | --- |
| 1 | Create the project, start watch mode, and set up debugging |
| 2 | Describe the data with types and interfaces |
| 3 | Create the sample data |
| 4 | Write reusable functions and higher-order functions |
| 5 | Check an unknown value with a type guard |
| 6 | Build one small service class |
| 7 | Connect everything and print a report |
| 8 | Inspect the planner with the debugger |
| 9 | Complete two small challenges |
| 10 | Review and check your work |

If you get stuck, use the hints to help you continue.

This is a **planner**, not a flight simulator. Each preview answers: "Could
Comet fly this mission with its current fuel, and what would the reward be?"
Creating a preview does not spend fuel or launch the drone.

### 1.3 Configure compilation

**Meet `npx`:** This command comes with npm and lets you run tools installed in
your project. You installed TypeScript locally with `npm i -D typescript`;
its compiler command is named `tsc`. Your terminal might not find that local
command if you type only `tsc`, so we use `npx tsc` to run the project's copy.
You do not need to install TypeScript globally.

1. Run `npx tsc --init`.
2. Replace the generated `tsconfig.json` contents with:

   ```json
   {
     "compilerOptions": {
       "target": "ES2020",
       "module": "CommonJS",
       "rootDir": "./src",
       "outDir": "./bin",
       "sourceMap": true,
       "strict": true,
       "noEmitOnError": true
     },
     "include": ["src/**/*.ts"]
   }
   ```

3. In `package.json`, replace only the `scripts` object with:

   ```json
   "scripts": {
     "watch": "tsc --watch"
   }
   ```

   Inside npm scripts, npm automatically finds locally installed commands.
   That is why these scripts use `tsc` directly, without `npx`.

4. Leave the package in CommonJS mode: if `package.json` has a `"type"` field,

**Understand the settings:** `rootDir` identifies the source folder; `outDir`
separates generated files; `sourceMap` connects JavaScript to TypeScript for
debugging. `strict` turns on stronger checks. `noEmitOnError` prevents a failed
build from writing new JavaScript.

## Step 2 - Describe the mission data

Create `src/models.ts`. All declarations in this file must be exported.

### 2.1 Add three ordinary union types

Copy these:

```ts
export type MissionId = string | number;
export type Direction = 'North' | 'South' | 'East' | 'West';
export type Difficulty = 'easy' | 'medium' | 'hard';
```

`MissionId` accepts two primitive types. The other two aliases accept only
specific string values.

### 2.2 Write two data interfaces

Use this first interface:

```ts
export interface Drone {
    name: string;
    fuel: number;
    active: boolean;
    position: [number, number];
}
```

Now write `export interface Mission` yourself, with these exact properties:

| Property | Type |
| --- | --- |
| `id` | `MissionId` |
| `title` | `string` |
| `direction` | `Direction` |
| `difficulty` | `Difficulty` |
| `fuelCost` | `number` |
| `reward` | `number` |

Do not add any methods or implementation to either interface.

The drone's `position` is a **tuple**: exactly two numbers in a known order,
`[x, y]`. A `number[]` array can have any length, so it would not communicate
that same requirement.

### 2.3 Name your function types

Add:

```ts
export type RewardRule = (reward: number) => number;
export type MissionPredicate = (mission: Mission) => boolean;
```

These are precise function signatures, sometimes called **lambda types**.
The `=>` here describes a type; it is not an executing function body.

Later, `(reward: number): number => reward * 2` will be an actual arrow function
that matches `RewardRule`. Avoid `Function`: it does not specify these useful
parameter and return constraints.

## Step 4 - Write the functional tools

Create `src/functions.ts` and add:


Export every function in this step.

### 4.1 Make an immutable generic helper

Implement:

```ts
export function addToArray<T>(items: T[], newItem: T): T[] {
    return [...items, newItem];
}
```

The same `T` connects the array's element type, the new item, and the returned
array. The spread operator copies the existing items into a new array.

Later you will use this with both strings and missions. It is not tied to either.

### 4.2 Higher-order function 1: return a function

Copy and read:

```ts
export function buildMultiplier(factor: number): RewardRule {
    return (reward: number): number => reward * factor;
}
```

`buildMultiplier(2)` does not immediately calculate a mission reward. It returns
a new function that remembers `factor`. Calling that returned function with
`40` produces `80`.

Implement this function:

```ts

    items: Mission[],
```

Replace the comment with one return statement. `filter` calls the predicate for
each mission and returns a new array containing the missions for which it
returned `true`.

**Hint:** The implementation is `return items.filter(predicate);`.

This is your second custom higher-order function: it **accepts** a function.
The first one **returns** a function.

## Step 5 - Validate a message from space

Create `src/guards.ts`. A radio message could contain a value that is not a valid
direction, even if your own source code is well typed.

Copy this complete guard:

```ts
import type { Direction } from './models';

export function isDirection(value: unknown): value is Direction {
    return typeof value === 'string' && (
        value === 'North' ||
        value === 'South' ||
        value === 'East' ||
        value === 'West'
    );
}
```

There are **two separate jobs** here:

1. **Runtime test:** The function body actually examines the value. `typeof`
   checks whether it is a string, and the comparisons check the allowed strings.
   This JavaScript still runs after compilation.
2. **TypeScript annotation:** `value is Direction` is a **type predicate**. It
   tells TypeScript that when the function returns `true`, the checked value
   can be treated as `Direction`. This annotation is erased during compilation.
   It does not perform any validation by itself.

TypeScript trusts a type predicate; it does not prove that the function body
checks the right things. Returning `true` for every string would be a bug even
though it could compile.

Do not write `value instanceof Direction`. `Direction` is only a type alias,
not a constructor that exists at runtime. Interfaces have the same limitation.

**Checkpoint:** Temporarily add these lines to `main.ts`, save, wait for zero
errors, and press **F5**:

```ts
import { isDirection } from './guards';

console.log(isDirection('North')); // true
console.log(isDirection('Up'));    // false
console.log(isDirection(42));      // false
console.log(isDirection(null));    // false
```

Then remove these temporary lines. You will use the guard in the final report.

> **Tip:** `unknown` means "we must check this before using it as a particular
> type." Unlike `any`, it does not turn off type checking.

## Step 6 - Add behavior with one service class

Create `src/mission-service.ts` with:

```ts
import type { Drone, Mission, RewardRule } from './models';
```

Use a class here because this object has behavior and configuration. The entities
themselves remain plain data. Keep filtering, mapping, and function creation in
the standalone functions you already wrote.

### 6.1 Initialize the service's fields in its constructor

Copy:

```ts
export class RescueService {
    constructor(
        public readonly stationName: string,
        private readonly rewardRule: RewardRule,
        private readonly launchFee: number
    ) {}
}
```

- The constructor's parameter properties create and initialize the fields.
- `public` allows code outside the class to read `stationName`.
- `readonly` prevents reassigning that property in TypeScript after construction.
- `private` makes `rewardRule` and `launchFee` accessible only inside this class
  during TypeScript checking. It is not a runtime security boundary.
- Passing a function into the constructor lets you change reward calculation
  without creating another class.

For example, `new RescueService('Orbit Rescue', buildMultiplier(2), 5)`
initializes a name, a reward function, and a launch fee. You will make this call
in `main.ts` later.
